# Self-Debugging Code Agent

An AI agent that takes a natural-language coding problem, plans an approach, writes code, tests it in an isolated sandbox, and automatically fixes itself when tests fail, looping until the solution passes or a safety limit is reached.

## Why this project

Most "AI coding assistant" demos are a single prompt → single response. This project is about what happens *after* that first response: can the system verify its own output, recognize when it's wrong, and correct itself without a human in the loop for every retry? That's the core skill behind real coding agents (Claude Code, Cursor's agent mode), and this is a small, fully-understood implementation of that same idea.

## How it works

```
User prompt
   │
   ▼
┌─────────────────────────────┐
│  PLAN                        │   Generates pseudocode, function
│  (pseudocode + test cases)   │   signature, edge cases, and test
└─────────────┬─────────────────┘  cases — before any code exists.
              ▼
┌─────────────────────────────┐
│  CRITIC                      │   A separate model call reviews the
│  (approve / list flaws)      │   plan for logic errors, missing edge
└──────┬───────────────────┬────┘  cases, and incorrect test cases.
       │ flaws found        │ approved
       ▼                    ▼
   REPLAN              LOCK plan + test cases
  (revise plan,            │
   loop back to Critic)     ▼
                    ┌─────────────────────────┐
                    │  WRITE CODE               │
                    └──────────┬─────────────────┘
                               ▼
                    ┌─────────────────────────┐
                    │  TEST (via MCP tool,       │
                    │  executed in an isolated    │
                    │  sandbox)                    │
                    └──────────┬─────────────────┘
                     fail │           │ pass
                          ▼           ▼
                     REFLECT      FINAL CODE
                   (fix code,      returned
                    loop back
                    to Test)
```

If the inner code-fixing loop repeatedly fails without passing, the agent escalates back to the **Plan** stage and replans from scratch — on the theory that if small code fixes keep failing, the *approach* itself may be wrong, not just the implementation.

## Key design decisions

- **The critic only reviews the plan, never the code.** Code correctness is objectively verifiable by actually running the tests, so a second LLM opinion adds cost with little benefit there. The plan — including whether its own test cases are even correct — has no such objective check, which is exactly where a second opinion earns its keep.
- **Test cases are locked once the plan is approved, and never regenerated by the code-writing step.** This prevents the model from quietly "passing" its own buggy code by rewriting the test cases to match whatever it produced.
- **Code execution is sandboxed**, not run with raw `exec()`. Generated code runs in an isolated environment with a timeout, so a bug (infinite loop, bad syscall) can't affect the host system or hang the agent indefinitely.
- **Tool access goes through MCP (Model Context Protocol)**, not a hardcoded function import. The test-running tool is a standalone server, independently testable and reusable by any MCP-compatible client — not just this agent.

## Tech stack

- **OpenAI API** (`responses.create`) with structured outputs (JSON Schema) for reliable, typed Plan/Critic objects
- **Pydantic** for schema definition and validation
- **MCP (Model Context Protocol)** — custom server exposing the code-testing tool, connected via a Python client
- **E2B** — isolated sandbox (Firecracker microVM) for executing untrusted, LLM-generated code
- **Starlette + SSE** — a lightweight web UI that streams the agent's progress live (planning → critiquing → generating → testing) instead of waiting silently for a final answer

## Setup

1. Clone the repo and install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
2. Create a `.env` file:
   ```
   OPENAI_API_KEY=your_key_here
   E2B_API_KEY=your_key_here
   ```
3. Run the CLI version:
   ```bash
   python agent.py
   ```
   Or run the web UI:
   ```bash
   uvicorn server:app --host 127.0.0.1 --port 8000
   ```

## Project structure

```
agent.py              # Main orchestration loop: plan, critic, replan, code, reflect
mcp_client.py          # Sync wrapper bridging the agent's loop to the async MCP SDK
tools.py                # MCP server: exposes the sandboxed test-running tool
pydanticBlueprints.py   # Plan, TestCase, Critics schemas
server.py               # Web UI backend (Starlette, streams agent events via SSE)
static/                 # Frontend (HTML/CSS/JS)
```

## Current limitations

- Scoped to **single-function, single-file problems only** — explicitly out of scope: multi-file projects, multiple functions per problem.
- Test cases are generated by the agent itself; if the critic misses a flawed test case, the agent can "succeed" against an incorrect spec. Known, accepted limitation for this version.
